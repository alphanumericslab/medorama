DatabasesRecordings

      

        

          

            
Add a database

            
Every patient's data comes from a database: a table imported into the catalog, or a database Medorama reads where it is. A row names its patient (patient ID, MRN or encounter); a file (an ECG, a recording, an image) always comes with its patient, never on its own.

            

              
              
              
            


            

              

                
                
              

              

              
              
A CLIF folder on the server
                
CLIF, the Common Longitudinal ICU data Format: its tables (CSV or Parquet) are recognised and imported in order, each a database (clif_vitals …). The folder must be inside data_roots; on the command line: medorama import-clif FOLDER.

                

                

              

              

                
                
                
              

              

              

              

                Imports run on the server: you may leave this page; the Import tab shows their progress.

            


            

              

                
                
                
                
                
                
                
                
                
                
              

              
SQL views (any layout)
                
Each a query with the canonical columns (docs/design/sources.md): persons, visits, entries; and a version query.

                

                  

              

              

            

          

          

            
Connected databases

            
Read where they are, never written. Their persons are linked to the catalog's patients as searches find them; Link all links them at once.

            

          

          

            
Import formats

            
Known exports, recognised by their columns and converted as they are imported. A site adds its own as TOML files in formats_dirs (docs/administration.md, "Import formats").

            

            

          

          

            
Sources

            
Everything imported carries a source. Removing a source takes what it added out of every patient's page;
              what another source also holds stays. Files are never touched.

            

            

          

          

            
Imports

            

          

        

      

    


    
    

      

        

          

            
Held-back rows

            
Rows in conflict with the catalog. Apply one with the fix it calls for, or dismiss it.
              Removing its import removes it too.

            

          

          

            
Possible duplicate patients

            
Same name and date of birth, names swapped, day and month of birth swapped, or same last name,
              first initial and date of birth. Merge them (no undo), or mark them as different people (not suggested again).

            

          

          

            
Recordings whose files disagree

            
Automatic links where the recording's own file names another patient than the databases.
              Keep the link (confirmed, linked manually from then on), or unlink (never linked to that encounter again).

            

          

          

            
Items waiting

            
Items whose patient or encounter no database names yet, by the keys they came with.
              They are matched as soon as a database names them.

Add-ons

            
Adapters: programs that read recording formats Medorama does not read itself (licensed formats). They are installed on the server, by an administrator: medorama addons install PROGRAM; never through this page.

            

          

          

            
Dates and times

            
How every page writes dates and times, for everyone, in the catalog's time zone (, set in its medorama.toml). Exports and the API keep ISO 8601 (2024-01-31 14:05), which every program reads.

Privacy Mode

            
What Privacy Mode withholds, for every user, on every page, in every file and in exports. It is always on for users without the PHI permission, and on by default for everyone but admins (the header's Privacy Mode switch). The server replaces what is withheld by placeholders ([Patient Name], [MRN] …) and patients by their pseudonyms. Pictures, PDFs, DICOM pixels and videos are sent as they are: their tabs are marked with a red triangle.

            

              

              
Dates move back by the offset below, and each patient's by a number of days of their own on top (from 0 to the days set here; 0: the same offset for everyone). A patient's own days are drawn once and kept, so every user and session sees the same dates for them; the time between any two of a patient's events is kept. The offset is counted on the calendar from 2000-01-01. Changing either changes the dates shown for every patient.
